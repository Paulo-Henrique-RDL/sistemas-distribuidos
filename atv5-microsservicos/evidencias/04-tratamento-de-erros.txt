===============================================================================
 EVIDENCIA 04 - Tratamento de erros (handle e Exceptions)
===============================================================================

Todos os servicos respondem no mesmo formato, com o campo "servico" dizendo
de onde veio a falha. Nenhum controlador tem try/catch: quem trata e a classe
TratadorDeErros, anotada com @RestControllerAdvice.

-------------------------------------------------------------------------------
400 - validacao: requisicao sem cliente e sem itens

{"momento":"2026-10-14T00:31:12.711231","status":400,"erro":"Bad Request","mensagem":"Dados invalidos. Verifique os campos informados.","caminho":"/pedidos","servico":"pedido-service","campos":[{"campo":"clienteId","mensagem":"Informe o cliente"},{"campo":"itens","mensagem":"O pedido precisa de pelo menos um item"}]}
-> HTTP 400

-------------------------------------------------------------------------------
404 - id inexistente no proprio servico

{"momento":"2026-10-14T00:31:12.808195","status":404,"erro":"Not Found","mensagem":"Pedido nao encontrado para o id 999.","caminho":"/pedidos/999","servico":"pedido-service"}
-> HTTP 404

-------------------------------------------------------------------------------
404 - id inexistente em OUTRO servico.
O pedido-service perguntou ao cliente-service, recebeu 404 e traduziu para um
404 proprio, com a mensagem certa. Sem esse tratamento seria um 500 generico.

{"momento":"2026-10-14T00:31:12.9028993","status":404,"erro":"Not Found","mensagem":"Cliente nao encontrado para o id 999.","caminho":"/pedidos","servico":"pedido-service"}
-> HTTP 404

{"momento":"2026-10-14T00:31:13.1170139","status":409,"erro":"Conflict","mensagem":"O pedido 2 ja esta cancelado.","caminho":"/pedidos/2/cancelar","servico":"pedido-service"}
-> HTTP 409

-------------------------------------------------------------------------------
503 - um servico de que dependemos nao respondeu

O catalogo-service foi encerrado (PID 28972). Esta e a situacao que so existe
porque o sistema e distribuido: no monolito, chamar outro modulo era uma
chamada de metodo que nao falhava por rede.

$ curl http://localhost:8200/actuator/health
  -> HTTP 000
  -> conexao recusada, o servico esta fora

$ curl -X POST http://localhost:8300/pedidos  (precisa do catalogo)
{"momento":"2026-10-14T00:31:19.2372157","status":503,"erro":"Service Unavailable","mensagem":"O servico catalogo-service nao respondeu. Tente novamente em instantes.","caminho":"/pedidos","servico":"pedido-service"}
-> HTTP 503

503, e nao 500: a causa e temporaria e de terceiro, entao faz sentido tentar
de novo. O nome do servico que falhou vai no corpo para facilitar o diagnostico.
